# October 25 upstream integration

This integration preserves stock Mia EAQ v1, optional matching Keys, C32,
8,650,752 shared logical KV tokens, the existing context aliases, vision,
structured outputs and random default sampling. Runtime qualification is in
progress; the retained deployment remains the rollback target.

The parser snapshot is pinned to `a90b0b5e7`; its JSON imports and HTTP test
callback are adapted to this fork. Blackwellboy's tool-only whitespace fix is
also included. Standalone parser tests now run in the Linux native server test
target, including malformed wrappers at every short length and streamed calls
at every character boundary.

The kit moves from HF `789625a7` to `4996441a`, a small intermediate update.
All 197 existing AOT variant records are unchanged. The five changed or added
files match recipe commit `58186d1` byte for byte; the only additional variant
is `_topk_sel` with N=KK=256. Newer unrelated kernels are not part of this update.

## Weights and other upstream changes

The review used Bertholomus's native TP2 `a57deb9d`, the earlier native branch
`fbbc9713`, and Mia recipe `27741e17`.

- Mia's recommended stock EAQ v1 revision remains `45ee5d0f`; the matching Keys
  repository remains `de412d22`. Both are already pinned here. No model download
  or overlay replacement is needed.
- [Mia EAQ v1.1](https://huggingface.co/Mia-AiLab/DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1.1-2.9-bpw)
  remains experimental. It introduces 27 BF16 linears inside the quantized pack,
  requires loader changes, and has no supported matching Keys configuration in
  Mia's recipe. Its model card leaves generation speed and selection beyond 32k
  untested. EAQ v1 remains this recipe's default.
- Bertholomus's newer 2.5-bpw checkpoint and C8 settings are different deployment
  choices; they do not replace our qualified Mia/C32 configuration.
- Our independent tokenizer/template scratch allocation, bounded graph and
  grammar caches, paired failure handling, aligned indexer row blocks, and
  rotating container logs already address several upstream concerns.
- Larger prompt scratch, tokenizer memo caching, sequential expert loading and
  distributed indexer optimizations need separate memory/performance evidence
  against this recipe's C32 reserve before adoption.
- Input special-token shielding and token-aware reply parsing are a separate
  semantic change. Mia's masking and Bertholomus's optional marker controls
  need a unified round-trip check for literal text, images and tool arguments.
  Those runtime options are not enabled by this integration.
- NVMe session caching remains disabled. No host memory floor, networking or
  display policy changes are included.

DSML parsing fixes establish how output is represented; they do not authorize
tool execution or establish resistance to natural-language prompt injection.
The client must still validate and authorize proposed calls.

## Qualification and rollback

Qualification results and the deployed source/image will be recorded here and
in [release status](../release/STATUS.md) after the candidate passes. Existing
headline throughput observations are not replaced by a short regression screen.

The update uses a separate owned installation. Retain the previous clean
checkout, image, immutable model assets and host restoration journals. Stop the
candidate with its own controller before starting the retained owner. If assets
were hardlinked, revalidate the retained owner's file identities: creating links
changes inode ctime, even though file contents remain unchanged. See
[rollback](ROLLBACK.md) and [migration rollback](MIGRATION-ROLLBACK.md).
