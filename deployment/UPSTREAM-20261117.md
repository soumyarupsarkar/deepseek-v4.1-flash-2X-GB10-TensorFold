# November 17 upstream review

The recipe keeps stock Mia EAQ v1, optional matching Keys, 32 active streams, an 8,650,752-token shared KV pool and a 1,048,576-token per-request ceiling. The startup profile defaults to 48 verification rows and offers a measured 64-row option for C32. The recipe also improves prompt replay, tool-client compatibility and admission when the KV pool is full.

## Assistant reasoning and tool sessions

By default the server replays the assistant's previous reasoning when the 1017 chat template calls for it. A client can use either `reasoning_content` or a nonempty string in `reasoning`. An existing nonempty `reasoning_content` takes precedence. This covers gateways that forward the vLLM spelling. [Mia 0047, nuk3s](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0047-replayed-reasoning.patch).

For clients that replay thinking across a long tool session, an operator can omit prior assistant reasoning when rendering the next prompt. Start a stopped pair with the option below. The response still contains the current turn's reasoning and the prompt still includes prior assistant answers, tool calls and tool results.

```bash
python3 cluster start --drop-reasoning-history
```

The head reports the effective setting as `drop_reasoning_history` in `/health`. A running stock/Keys switch preserves it, including recovery after a failed switch. Starting again with plain `python3 cluster start` restores normal replay. A paired stop clears retained in-memory sessions. Mia observed loops on three of six targeted replays with history and zero of six with history omitted. Those six observations came from two points in one problematic conversation at three seeds. They support offering the option to affected clients. [Mia 0057, marknx](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0057-drop-reasoning-history.patch).

Omitting previous thinking can shorten the next prompt. It also removes intermediate work that a subsequent turn might need. Normal replay remains the default.

## Short tails and KV pressure

Mia 0045 lets a request interrupt a long prefill when its *remaining* prefill is small. Our scheduler already checks the actual token position after restore. A text continuation with at most one 2,048-token chunk left can finish between chunks of another request. If placement costs the retained prefix, scheduling uses the new cold position. Image requests still run through normal prefill because their placeholder token IDs alone cannot distinguish pictures. [Mia 0045, Dick Lai](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0045-cut-in-tail.patch).

- A request refused for lack of KV space keeps its place in the queue. Smaller requests that fit can proceed. Each refused request gets at most one attempt between stream completions, and the oldest eligible request within each foreground/background priority gets the first retry. [beastllama's Bertholomus PR 55](https://github.com/bertholomus/TensorFold/pull/55).
- The DeepSeek backend now evicts snapshots when a new snapshot is saved. Before attempting placement it checks whether the request could fit even with perfect compaction. An impossible admission therefore preserves unrelated cached prefixes on both ranks. [beastllama's Bertholomus PR 54](https://github.com/bertholomus/TensorFold/pull/54).
- Prefix lookup chooses the longest usable snapshot. An overwritten backing extent, or a cut too close to the prompt end for the model's replay window, can no longer hide a shorter usable prefix. A later save can refresh a stale entry under the same token key. [Mia PR 134](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/pull/134).
- Multi-image preparation reuses scratch storage between pictures. Only each aligned final payload lives for the full request. GET and DELETE now consume optional request bodies before reusing an HTTP connection. [Mia 0056, marknx](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0056-server-picture-prepare-scratch.patch) · [Mia 0046, Christopher A. Williamson](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0046-server-get-delete-body-discard.patch).

## 48 versus 64 verification rows

One verification row per active stream advances its target token. At C32 a 48-row round has room for up to 16 additional proposals. A 64-row round has room for up to 32. The allocator chooses proposals according to their estimated benefit and cost. This setting is independent of the C32 admission limit, the logical KV pool and the context aliases. The native health report now exposes the configured `native.round_rows`.

| On Bertholomus's two GB10s | v0.7.4 | v0.7.5 |
|---|---:|---:|
| Configured resident streams / verification rows | 16 / 32 | 32 / 64 |
| C16 sustained aggregate tok/s | 200.0 | 217.9 |
| C32 sustained aggregate tok/s | 198.2 | 248.6 |

The C32 result is a 25.4% gain for their complete release. That comparison also changed the stream cap, cost table, kernel kit and pool. Their calibration gives 176.4 ms at 48 rows and 218.2 ms at 64, so a wider verification pass needs more accepted tokens to pay for its extra time. Our baseline already admits 32, uses a different quant, and calibrates its own drafting policy. Bertholomus's 2.5-bpw profile has a 7,340,032-token pool. [Bertholomus v0.7.5 measurements and protocol](https://github.com/bertholomus/deepseek-v4.1-tensorfold-tp2-2xgb10/tree/2f252f4a6c254242c374a40f38d7e5cb979db862#v075-2026-11-04-rounds-of-64-rows-pools-of-32-streams).

### Measurements on this recipe

All three runs used the same AArch64 binaries, kernel kit, stock Mia 2.9-bpw weights, 32 stream slots and shared pool. The first 64-row run extended our local cost table linearly above row 48. The calibrated run kept rows 1–48 identical and scaled Bertholomus's 49–64 measurements to our 48-row price. That put the estimated cost at row 64 at 239.34 ms, down from 257.98 ms with linear extrapolation. The scheduler consequently selected wider rounds more often. [Upstream cost curve](https://github.com/bertholomus/deepseek-v4.1-tensorfold-tp2-2xgb10/blob/2f252f4a6c254242c374a40f38d7e5cb979db862/config.env.example) · [Trial engine](https://github.com/soumyarupsarkar/deepseek-v4.1-flash-2X-GB10-TensorFold/commit/445c7a9ca2eac22e1550cb9a62743a9561c5dfc7).

| C32 synthetic workload | 48 rows | 64 linear | 64 calibrated | Calibrated vs 48 | End-to-end change |
|---|---:|---:|---:|---:|---:|
| Code, greedy | 331.1 | 349.8 | **382.7** | +15.6% | +11.6% |
| Prose, greedy | **278.1** | 270.8 | 274.0 | −1.5% | −0.9% |
| Counting, greedy | 389.8 | 387.3 | **419.6** | +7.6% | +7.4% |
| Mixed, temperature 1 | 280.5 | 277.8 | **310.4** | +10.6% | +1.9% |

Rates are median aggregate decode tok/s when all 32 streams were decoding, over two 160-token repetitions in opposite workload orders. End-to-end includes the rest of each wave. All 256 scored short replies in **each** 64-row policy matched the 48-row token hashes. Each policy also matched its ordinary-decoding control on all 32 sampled streams. The ordinary control measured 244.8–245.8 tok/s across the three launches. In the linear run, code and prose never exceeded 48 rows. In the calibrated code run, 134 of 135 timed full-occupancy verification rounds exceeded 48. The README headline table uses a separate workload protocol.

The capacity test primed one identical 261,120-token synthetic document, then launched 32 independent active reservations for two waves of 1,024 generated tokens per stream. Each stream reached exactly 262,144 total tokens and restored at least 260,096 cached tokens. Full-wave rates include residual prefill and decode. This exercises a heavily shared prompt and does not time 32 unrelated cold documents.

| Profile | Full-window aggregate tok/s, waves 1 / 2 | Timed C32 rounds above 48, waves 1 / 2 | Minimum available RAM, head / worker |
|---|---:|---:|---:|
| 48 | 171.1 / 170.4 | 0 / 0 | 2.38 / 4.11 GiB |
| 64 linear | 175.0 / 176.4 | 347 / 322 | 2.85 / 2.99 GiB |
| 64 calibrated | 178.2 / 178.2 | 311 / 379 | 2.54 / 3.88 GiB |

All six waves reached 32 simultaneous decoders. The 32 per-stream seeded outputs replayed exactly on each policy, and all 64 comparisons against the 48-row baseline matched for each wider policy. The 2 GiB paired guard stayed active.

At the million-token ceiling, 16 extra rows request 192 MiB per rank for index keys and scores. The candidate mask, block maxima and tile maxima bring those five buffers to 204 MiB extra per rank. On these launches the worker arena reported 248.8 MiB more used and reserved 192 MiB more. The head allocator reported 192.0 MiB more active after the short workload. These are separate views of memory. Linux `MemAvailable` also varies between launches. An earlier full-window run came within 26.6 MiB of the 2 GiB head guard. [Historical full-window measurements](../benchmarks/NATIVE-DRAFTING.md) · [Bertholomus's expert-boundary change](https://github.com/bertholomus/TensorFold/commit/c79c714ca3e6898ad8dfd6226cea7992b744cf4e).

**Selection.** Start a stopped pair with `python3 cluster start --round-rows 64` for the calibrated policy. The head and worker receive the same width and prices. The normal start uses 48, which retains more working memory and performed best on prose. A running stock/Keys switch preserves the width. The hardware comparison used stock Mia. Keys at 64 and multi-hour endurance at 64 remain unmeasured. To return to 48, drain requests, issue a paired stop, then start normally. Confirm the configured width in `/health` under `native.round_rows`. [Aggregate measurements, per-wave timings and output parity](../release/native-verify-rows-20261117.json).

To repeat the full-window comparison on a dedicated installation bound to `127.0.0.1`, select the width at startup, then run the following with a fresh record name for each launch. The short-workload table uses kit prompt set B and the fixed seeds recorded in the numeric evidence.

```bash
python3 tools/qualification/native_qualification.py memory --record verify64-stock-full \
  --streams 32 --rounds 2 --initial-tokens 261120 --growth 0 --reply-tokens 1024 \
  --shared-prefix --identical --require-concurrency --require-replay-parity
```

## Other changes considered

| Change | Decision and tradeoff |
|---|---|
| Responses compatibility | Adopted Mia 0058. Clients can request `include: ["reasoning.encrypted_content"]` and receive the server's ordinary plaintext reasoning item. Replaying an opaque encrypted item still requires the original plaintext. Other unsupported include values still get an actionable error. [Mia 0058](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0058-responses-include-encrypted.patch) |
| Numeric reasoning effort | Adopted Bertholomus PR 53. Chat Completions and Responses clients can pass any integer from 1 through 100, including as a string of digits. This chooses the template's effort instruction. An explicit thinking-token limit remains a separate setting. Existing named levels keep their recipe values. [Bertholomus PR 53](https://github.com/bertholomus/TensorFold/pull/53) · [Official 1017 template](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/blob/08c8657f02291e11b6f6b63e0e16014f8e748518/chat_template.jinja) |
| Long-context monitoring | Adopted the 10, 20, 30, 40 and 60 minute histogram boundaries from PR 52. The previous last finite bucket was five minutes. Each histogram emits five extra time series on a scrape. The proposed per-session accounting is more involved because a live stream and retained snapshots may refer to overlapping rows. Counting each snapshot's length would overstate resident usage. [Bertholomus PR 52](https://github.com/bertholomus/TensorFold/pull/52) · [Mia PR 137](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/pull/137) |
| Reserved short-request lanes | Kept all 32 slots open to any request. In the author's 8-slot saturation test, two reserved lanes cut short-request p95 time to first token from 58.38 to 5.53 s. Long-only throughput fell 10.3%, and the mixed cached benchmark saw little change. Our short-tail cut-in and retry queue address delays when space is available. [Mia PR 144 and author measurements](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/pull/144) |
| Full snapshot backing, disk spill and KV sharding | Independent backing preserves prefixes after their working rows are overwritten, at a memory cost that grows with the saved position. Spill can survive a restart at the cost of SSD writes and restore latency. The recipe keeps its in-memory cache and falls back to a shorter usable prefix. [Bertholomus PR 56](https://github.com/bertholomus/TensorFold/pull/56) · [Mia's storage patches](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/README.md) |
| Malformed tool output | Adopted Mia 0067. If tools were offered and the whole answer contains only DSML closing tags, Chat Completions and Responses label it `orphan_dsml_closers` in their final metadata. Operators can correlate a warning with the request ID. The generated answer is preserved, and retry remains a client decision. [Mia 0067, hecisaza and SvangenStudios](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/pull/128) |
| DSML streaming and log probabilities | The whole-block bounds check from Mia 0064 is already present. Mia 0065 can preserve calls whose literal parameter contains the outer DSML closing tag. It changes where streaming commits a call and how a second parse resolves ambiguous boundaries. Incremental arguments can make tool progress visible sooner, but partial calls, literal closing tags and truncated streams must agree across Chat, Responses and Messages. The optional logprob implementation copies logits to the host for participating rounds and still needs two-rank parity and throughput evidence. [Mia 0065](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0065-dsml-value-holds-closer.patch) · [Bertholomus PR 57](https://github.com/bertholomus/TensorFold/pull/57) |
| Graph fallback, loader read-ahead and RDMA affinity | Eager fallback can rescue a recoverable graph-capture failure. Our pair already has the drafter ownership fix and bounded graph eviction. A wider fallback needs paired failure-recovery tests on that implementation. Mia's loader can prefetch up to 4 GiB ahead during startup. Its optional proxy affinity showed no large temperature improvement in the two-Spark test. We kept the current loader and idle backoff. [Bertholomus PR 45](https://github.com/bertholomus/TensorFold/pull/45) · [Mia 0066](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0066-load-prefetch.patch) · [Mia 0068](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/c7f2b85100f0a7b099c92a4e21825e30d93c9c51/zig/patches/0068-rdma-proxy-cpus.patch) |

## Validation

The integrated source passed 408 native tests from a fresh Zig cache, 92 publication tests and 25 deployment-controller tests. These include the 64-row expert boundary, queue ordering and prefix fallback under pressure, two-rank launch arguments, width and history preservation on failed weight switches, and numeric effort reaching the rendered template. A local HTTP run against the compiled native server with a scripted backend checked the Responses include hint, opaque-only input, unknown includes, long latency buckets, and 18 whole/streaming tool-output cases across Chat Completions, Responses and Messages.

The GPU router checker compared 16,003,520 words per GB10 across widths 1–64 with zero mismatches. The isolated paired inference trial used a single binary pair for all three policies. The worker GB10 also compiled the integrated native server, worker and router checker at `744f2fe8` with embedded SM121 kernels. All 13 Zig engine/build files changed by the width prototype match the integrated source byte for byte. The API and controller additions were checked on the integrated source. [Build digests and test counts](../release/native-verify-rows-20261117.json). The previous LAN image was restored after the trials.

The reviewed revisions are Mia `c7f2b85100f0a7b099c92a4e21825e30d93c9c51`, Bertholomus's recipe `2f252f4a6c254242c374a40f38d7e5cb979db862` and his TP2 engine `c9c709534d0fa64cd62bded064e929df6f8f797d`. Bertholomus PRs 52–57 and Mia PRs 134 and 137 were open at review time. Mia PR 144 was closed without merging.

## Rollback

Use a separate checkout, image and deployment owner when installing this source. Keep the previous installation's images, configuration, data and journals. To return to the previous runtime, drain the new pair, run `python3 cluster stop` and `python3 cluster check-host` from its checkout, then run `python3 cluster start --variant stock` and `python3 cluster status` from the retained checkout.
