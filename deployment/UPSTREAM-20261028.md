# October 28 upstream maintenance

This update reduces CPU use while the two ranks are idle and fixes drafter
graph ownership on a failed first launch. Stock Mia EAQ v1, optional matching
Keys, C32, the 8,650,752-token shared pool, aliases, vision and structured
outputs keep their existing configuration.

## Changes selected

| Change | Reason | Credit |
| --- | --- | --- |
| Native RDMA idle backoff | The proxy otherwise spins one CPU core per rank with no requests. After two seconds without posts or completions, it requests a 100 µs sleep between polls. Activity restores spinning. | [willjriley's original Python change](https://github.com/bertholomus/TensorFold/pull/27), [Mia's native port](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/blob/27741e176a9e5b98c10c9c7d012fd3e4fcdc19b6/zig/patches/0010-rdma-idle-nap.patch), and [wiseares's TP2 adaptation, issue 32](https://github.com/bertholomus/deepseek-v4.1-tensorfold-tp2-2xgb10/issues/32) |
| Drafter graph ownership after insertion | A failed first launch could destroy an executable that remained in the cache, allowing reuse of a freed handle or a second destruction. The cache now owns it once insertion succeeds. The main round cache already follows this rule. | [nuk3s, Bertholomus TensorFold PR45](https://github.com/bertholomus/TensorFold/pull/45), adapted narrowly to this fork |

The idle policy keeps this fork's existing failure-report ordering. Its pure
state-machine tests cover disabled mode, active polling, sparse clock reads,
the full quiet period and wake/reset behavior. Additional host tests inject
first-launch and allocation failures into the drafter cache. The gather test
can use the embedded serving kernel and insert quiet gaps before each burst
and shutdown.

`TF_RDMA_IDLE_S=2` and `TF_RDMA_NAP_US=100` are explicit in the deployment
profile. At engine startup, setting `TF_RDMA_IDLE_S=0` disables backoff. Idle
seconds accept finite values from 0 to 3,600; naps accept integer microseconds
from 1 to 1,000,000. The requested nap duration is not an upper bound on OS
scheduling delay. These are container settings; the only timer-slack change
applies to the proxy thread and ends with that process.

## Validation and deployment

All 12 finite stock gates passed across 32.5 minutes on the original
rank processes: baseline serving, strict output, sampling, aliases, protocols,
image formats, greedy/sampled drafting parity at C4/C8/C16/C24/C32, retention,
prefill responsiveness, partial-prefill compaction and decode compaction.
The retention fixture used 32 distinct 16k prefixes, exact replays and extensions.

During those checks, 369 paired monitor samples recorded no failures.
Minimum sampled available RAM was 3.16 GiB on the head and 2.82 GiB
on the worker, above the unchanged 2 GiB guard. Changing workloads do not
establish a long-term memory trend.

Stock → Keys → stock preserved aliases and replayed all six stock canaries
exactly. Both ranks independently reported the intended overlay; Keys added
zero resident weight bytes and passed baseline/structured-output checks.

The separate LAN installation repeated full preparation and tensor comparison,
then passed 12 fresh synthetic requests covering aliases, schema, tools, vision,
random seeds/replay and streaming. Worker-to-head LAN reachability, both-rank
stock selection and the paired monitor passed. The tested image remains pinned
in the serving checkout; the public development branch includes later evidence
and documentation commits.

The image build passed all 379 native tests, one C++ grammar test, and the
publication/controller suites passed 92 + 23 Python tests. Both hosts passed
nine GPU preparation checks. All 143,770 stock tensor entries, covering
106,107,109,192 bytes per rank, compared exactly; the optional Keys cache's
78 entries and 341,266,432 bytes per rank also matched.

Real paired RDMA tests passed with backoff enabled and disabled, using the
embedded serving kernel, rows 1/6/16/48, width 2,560 and 500 repetitions each of
gather and gather-into. Three-second quiet gaps preceded each timed burst and
shutdown. Both ranks reported zero mismatches and completed without failure.

Full-window C32 replay and cold million-token retrieval were qualified in the
[October 25 update](UPSTREAM-20261025.md). This maintenance update leaves the
pool, slot and context limits unchanged; it does not rerun that capacity campaign
or constitute a new endurance or model-quality evaluation.

## Rollback

Retain the preceding checkout, exact image, data and its own ownership and host
restoration journals. Stop the new pair and check host restoration with its
controller before using the retained owner's controller to start stock again.
No reboot or weight download is required while those files remain intact.

Hardlinks change inode ctime. Revalidate runtime assets and every prepared
tensor byte with the retained image; compare each original prepared-file
SHA256 before refreshing the import receipt's ctime fields. Refresh the Keys
verification receipt too. Do not copy host journals between installations or
silence changed-fingerprint checks. The private cutover records these checks
after its final asset reuse.
