# Mia EAQ 1017 weights on this recipe

This migration changes the weight pack to [Mia-AiLab's 1017 EXL3 EAQ v1
2.9-bpw conversion](https://huggingface.co/Mia-AiLab/DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1-2.9-bpw).
It retains this repository's native TensorFold engine, **32 active slots**,
**8,650,752 pooled logical KV tokens**, **1,048,576 tokens per request**,
vision, structured output, random sampling, aliases and paired recovery.
Mia's serving recipe was a compatibility reference; its server settings and
four-stream defaults are not substituted for this deployment.

Stock Mia is the default. The matching optional [Keys sidecar](KEYS-1017.md)
is prepared separately and selected by restarting the pair. Switching does
not redownload weights or rewrite the stock cache.

[The model manifest](config/assets.json) pins every source shard and metadata
file. [The overlay manifest](config/keys-1017.json) separately pins
`exl3_wo_b_l10_35_mia29.safetensors` and its complete tensor layout. The older
`exl3_wo_b_l10_35_1017.safetensors` was qualified with the previous LibertAIDAI
pack; it is not the overlay selected by this Mia profile.

The Mia pack contains 39 source shards, totaling 210,601,036,966 bytes. Its
architecture and tokenizer match the reviewed original 1017 checkpoint.
The vision-routing bias values, shapes and dtypes match the original pinned
vision extraction. Engram tables, native kernel kit and this recipe's reviewed
chat template remain unchanged.

The confidence head is stored as **FP16** in Mia's pack. The native preparation
plan and loader require that dtype and preserve its source bytes; runtime
conversion happens in the engine. A graft script that casts it to FP32 is not
part of this setup. The MTP dense projections use Mia's K4 quantization rather
than the previous pack's K6. Draft acceptance and throughput must therefore
be measured, rather than inferred from the shared nominal 2.9-bpw label.

The matching Keys overlay replaces only `wo_b` projections in layers 10–35.
Both the Mia originals and replacements are EXL3 K5. Experts, MTP, Engram,
vision and all remaining model tensors retain the Mia stock bytes. The
reader accepts a complete uniform K5 or K6 overlay on a K5 base, rejects mixed
widths and unexpected names, and checks each prepared tensor against its
pinned source. This profile selects only the Mia K5 sidecar.

## Qualification

Both stock and matching Keys passed **all 21 finite checks**, including
vision, strict schemas/tools, sampling/replay, aliases/protocols, drafted/plain
parity, retention, pool limits and all three compaction modes. Each variant
passed two full **32 × 262,144-token** waves with 32 simultaneous decoders and
exact token replay. That test primes a shared document and reserves independent
active extents; it does not measure 32 unique cold 262k prefills. Each also
completed a cold **1,048,320-input + 256-output** request, with zero cached input,
and recovered all three embedded passphrases.

The fresh matched stock comparison contains all 48 waves / 792 requests per
pack. Mia's six C32 median rates improved **0.10–2.57%**. C1 ranged from
**−6.22%** (sampled code) to **+11.37%** (sampled prose). Reply and draft behavior
can change with the weights. [All rates, repetitions and the separate draft
diagnostic](../benchmarks/MIA-1017-COMPARISON.md) preserve that tradeoff.

Stock loaded weight allocation is **106,110,129,620 bytes per rank**,
**79.97 MiB less** than the retained LibertAI stock deployment. The matching
Keys K5 replacement adds **zero resident GPU weight bytes** on either rank.
The 8,650,752-token pool, 32 slots, million-token ceiling and 2 GiB monitor
guard remain unchanged.

The bounded diagnostics used a one-hour stock timer and a half-hour Keys
timer, with normalized quiet windows before and after. They interleaved C32
text, schema, tool and image requests with single cold deep-context requests:

| --- | ---: | ---: | ---: | ---: |
| Mia stock | 65.1 min | 28 | 5 | 1,379 |
| Mia keys | 34.6 min | 25 | 2 | 1,085 |

| Variant | Host | Lowest sampled available RAM across validation | Quiet-window rank anonymous + swap change |
| --- | --- | ---: | ---: |

Quiet-window memory compares rank anonymous memory plus swapped anonymous
pages after matching retained-cache normalization and at least two idle
minutes. Available RAM also reflects OS paging and caches. There were no
observed OOM increments, poisoned/RDMA errors, paired-monitor failures or rank
restarts during these runs. The full-window lows above include the throughput
and finite capacity checks, not just the later diagnostic.

The earliest approximately 35 minutes of stock retain one-minute monitor
observations; the older fine-grained files had rotated out. Later stock and
all Keys observations retain the roughly five-second series. The report
records actual sample gaps and preserved-file hashes. These are sampled
minima; the two diagnostic runs also retain their separate observation series.

The stock → Keys → stock → Keys → stock rehearsal replayed six fixed-seed
synthetic prompts identically within each variant, kept aliases and base-cache
identities unchanged, and ended on stock. A fresh LAN installation of the same
tested source/image then passed twelve synthetic startup requests and remote
LAN reachability checks, with zero overlay entries on both ranks.

## New installation

Follow the [installation runbook](README.md) with a clean checkout, a new
configuration and dedicated data roots. The normal sequence is:

```bash
python3 cluster plan
python3 cluster doctor
python3 cluster init
python3 cluster fetch
python3 cluster replicate
python3 cluster verify
python3 cluster build
python3 cluster prepare
python3 cluster precompile
python3 cluster start --variant stock
```

Use an external `HF_TOKEN_PATH` if access requires authentication. The token
does not enter the image or inference containers. Keep all completed
verification and restoration receipts in `deployment/.local/`.

To prepare Keys, stop both ranks and run `cluster setup-keys`, then start with
`--variant stock` to leave the optional overlay off. Later, drain requests and
use `cluster switch --variant keys` or `cluster switch --variant stock`.
Both ranks restart and retained KV sessions are discarded. Model aliases stay
the same. See [Keys setup and loaded-variant inspection](KEYS-1017.md).

## Reversible migration from the previous pack

1. Preserve the previous clean source revision, image on both hosts, local
   configuration, complete installation journals and immutable model inputs.
   A Git commit alone does not preserve weights or host recovery state.
2. Stop the previous pair through its owning checkout and run its
   `cluster check-host`. Create the Mia installation with a separate name,
   checkout and data roots; capture fresh host baselines with `cluster init`.
3. Download the new model into the new roots. Reuse only independently verified
   compatible immutable Engram/kit files. Do not reuse a LibertAIDAI prepared
   rank cache as a Mia cache. Never copy another installation's ownership,
   launch or host restoration journals.
4. Build, prepare and compare every tensor on both ranks. Qualify on loopback
   before moving the same tested source/image to the intended LAN bind.
   Compare matched C1/C32 workloads and memory with unchanged pool, slots and
   guard floors. A successful startup alone is not a cutover qualification.
5. Keep the previous deployment's required bytes available. If worker storage
   is reclaimed, first hash each exact file and its head-side backup and record
   every hardlink destination. Keep enough recoverable storage for both the
   source pack and prepared worker cache. Document the copy-back procedure
   before removing any worker copy.

Creating hardlinks changes inode metadata. Refresh affected installations'
full content-verification receipts before reusing them; do not bypass a stale
identity check or replace live restoration journals with saved snapshots.

## Restore the previous deployment

In the **Mia installation's owning checkout**, run:

```bash
python3 cluster stop
python3 cluster check-host
```

Restore any reclaimed worker files from their verified backups. Check free
space first; if Mia files must be removed from that worker, back up and verify
its unique prepared cache as well as its source weights before deleting exact
recorded names. Recreate the previous hardlinks, verify all hashes and refresh
its content identities. Broad directory removal and Docker pruning are not
required.

Then, in the **retained previous checkout**, verify its own prepared inputs
and start its stock variant:

```bash
python3 cluster verify
python3 cluster precompile
python3 cluster start --variant stock
python3 cluster status
```

Check both rank images, loaded variant, aliases, capacity and paired monitor.
No routine reboot or persistent network/display change is required. Stopping
Mia and passing `check-host` is sufficient to restore its captured host state
while leaving inference off. Full model rollback additionally requires the
retained assets and the copy-back work described above.
